# Nearest Quest Tracker (NQT) — план 2.0: локации и своё окно

Работа идёт в отдельных сессиях, по одному этапу или подэтапу за сессию.
**В начале каждой сессии:** прочитать этот файл (раздел «Статус» и нужный этап), затем
`..\FALLOUT4_MOD_DEVELOPMENT_GUIDE.md` (разделы 1 и 2). Находки по движку, сборочный стек,
устройство хоткеев/маркеров/данных стартов — в **`PLAN-1.0.md`** («Решения и находки», «…: сделано»);
читать нужный раздел оттуда, а не выводить заново.
**В конце сессии:** обновить «Статус» и «Решения и находки», дописать сценарии новой функции
в «Чеклист полевого теста».

План 1.0 (`PLAN-1.0.md`) закрыт 2026-10-04: пользователь проверил мод в игре, основные функции
работают. Мелкие баги чиним отдельно по мере обнаружения (раздел «Баги»), не дожидаясь этапов.

Префикс, файлы, раскладка проекта — как в 1.0: `NQT`, `NearestQuestTracker.esp` (ESL),
`NearestQuestTracker.dll`, MCM `Data\MCM\Config\NearestQuestTracker\`, папки `papyrus/`, `tools/`,
`f4se_plugin/`, `mod/`. Новое: исходники окна — `menu/` (AS3), готовый SWF — `mod/Interface/NearestQuestTracker.swf`.

## Решения и находки

- **Своё окно, а не правка Pip-Boy** (2026-10-04). SWF Pip-Boy заменяют интерфейсные моды (у пользователя
  лежат свои `PipboyMenu.swf`, `Pipboy_InvPage.swf`, `Pipboy_MapPage.swf`), замена файла даст конфликт.
  Своё меню со своим SWF ни с кем не конфликтует.
- **F4SE 0.6.23 умеет свои меню** (проверено по строкам `Data\Scripts\UI.pex` и `f4se_1_10_163.dll`,
  2026-10-04): `UI.RegisterCustomMenu`, `RegisterBasicCustomMenu`, `OpenMenu`, `CloseMenu`, `IsMenuOpen`,
  `IsMenuRegistered`, `Invoke`, структура `MenuData` (`menuFlags`, `movieFlags`), класс `CustomMenu` в DLL.
  Альтернатива — регистрировать меню прямо из нашей DLL через CommonLibF4 (`RE::UI`, `IMenu`); выбрать в 3a.
- **Тип квеста в данных игры** (QUST `DNAM` = flags u16, priority u8, formVersion u8, delay f32, **type u32**;
  посчитано по мастерам 2026-10-04, скрипт был во временной папке — повторить по `tools/esm.py`):
  0 нет, 1 основной, 2 Братство Стали, 3 Институт, 4 Минитмены, 5 Подземка, 6 Разное, 7 Побочный.
  В Fallout4.esm разбивка осмысленная (1: 34, 2: 38, 3: 33, 4: 29, 5: 21, 6: 328, 7: 63, 0: 790 — служебные).
  В дополнениях почти всё — 0/6/7 (даже основные квесты DLC: `DLC03MQ01` = 7, `DLC04MQ03` = 0), подразделов
  вики («акты», «Даймонд-сити», «повторяющиеся», «неотмечаемые», ветки Фар-Харбора) в данных **нет**.
  Значит, категории как на вики — только из таблицы, собранной с вики (этап 2); тип из `DNAM` — запасной
  вариант для квестов других модов.
- **Вики отдаёт таблицы квестов с ID** (2026-10-04). WebFetch получает 402, а MediaWiki API через curl работает:
  `curl -A "Mozilla/5.0" "https://fallout.fandom.com/api.php?action=parse&page=Fallout_4_quests&prop=wikitext&format=json&formatversion=2"`,
  русская: `https://fallout.fandom.com/ru/api.php?...&page=Квесты_Fallout_4` (имя в URL-кодировке).
  - en: у каждой таблицы колонки Form ID (`{{ID|0001ed86}}`, у дополнений `{{DLC ID|001b3f}}`) и Editor ID;
    191 ID в основной игре + 89 в дополнениях. «Третий акт» — список ссылок, без таблицы.
  - ru: те же ID (`{{ID|…}}`, `{{DLC ID|…}}`, `{{DLC_ID|…}}`), 183 в основной игре; структура разделов — та,
    что нужна пользователю (Даймонд-сити, Добрососедство, Убежище 81, Кэботы, Банкер-хилл, ветки Фар-Харбора…).
  - У `DLC ID` нет индекса плагина — плагин определяется по разделу (Automatron → DLCRobot.esm,
    Far Harbor → DLCCoast.esm, Vault-Tec Workshop → DLCworkshop03.esm, Wasteland Workshop → DLCworkshop01.esm,
    Nuka-World → DLCNukaWorld.esm).

## Этап 1 — ближайшая непосещённая локация

### 1a. Исследование (отдельная сессия)
Ответить проверкой (дизассемблер, `Fallout4.pdb`, минимальный тест), не по чужим описаниям:
- Где движок хранит маркеры карты и их состояние: флаги маркера (виден на карте / можно быстро
  переместиться), как отличить «не открыт», «замечен издалека», «посещён». Папирус-аналоги для сверки:
  `ObjectReference.IsMapMarkerVisible`, `CanFastTravelToMarker`, `AddToMap`.
- Как перечислить все маркеры карты во время игры (включая маркеры других модов), или придётся собирать
  список из ESM генератором, как `QuestStarts.json`, а в игре только читать состояние.
- Название локации для уведомления/окна: имя маркера карты, `BGSLocation`, мир (Содружество / Фар-Харбор /
  Ядер-Мир) — для порядка по мирам, как в 3d.
- Подходит ли расстояние из 1.0 (путь движка, «входы» — `PLAN-1.0.md`, «3b/3d: сделано») для точки,
  у которой нет цели квеста, или считать по прямой с порядком по мирам.
- Как ставить маркер: тот же механизм, что маркер старта (алиас + цель квеста в «Разном», `PLAN-1.0.md`, «3b»),
  отдельной целью «Локация: …».

### 1b. Хоткей + MCM (отдельная сессия)
- Хоткей «Ближайшая непосещённая локация»: ставит маркер, уведомление «Локация: X».
  Повторное нажатие / отдельный хоткей — снять маркер. Маркер снимается сам, когда локация посещена.
- MCM: какие локации считать — **только замеченные** (по умолчанию: без спойлеров) или **все, включая
  не открытые**; исключить поселения?; хоткей «исключить эту локацию» по образцу исключений квестов.
- Минимальный тест: нажать хоткей рядом с непосещённой отмеченной на карте локацией — появился маркер.

## Этап 2 — категории квестов (данные)

- Генератор `tools/gen_quest_categories.py`: берёт wikitext ru- и en-страниц через API (кэш в `tools/cache/`,
  в репозиторий не класть, если там чужой текст — класть только итоговый JSON с ID и названиями категорий),
  разбирает заголовки разделов и `{{ID|…}}`/`{{DLC ID|…}}`, сверяет каждый ID с QUST в мастерах (`tools/esm.py`),
  пишет `mod/F4SE/Plugins/NearestQuestTracker/QuestCategories.json`:
  дерево категорий (ключ, ru/en название, порядок) + для каждого квеста путь категории.
- Дерево — по русской странице (разделы, которые перечислил пользователь 2026-10-04):
  1 Основные (Пролог, Акты 1–3) · 2 Фракционные (Минитмены / Братство / Подземка / Институт × основные,
  побочные, повторяющиеся) · 3 Побочные (нефракционные и «Разное» по городам, неотмечаемые, напарники,
  поселения) · 4 Дополнения (Automatron, Far Harbor с ветками, Vault-Tec Workshop, Wasteland Workshop,
  Nuka-World). Английские названия — по en-странице.
- «Третий акт» на вики — список ссылок без ID: квесты взять по названию ссылки / editor ID вручную.
- Квесты, которым категорию определить не удалось (другие моды, CC, ванильные, которых нет в таблицах вики):
  отдельная категория верхнего уровня **«Другие квесты» / «Other quests»** (решение 2026-10-04), последней в дереве;
  внутри — подгруппы по плагину. Не «Остальные»: так на вики уже называются подразделы «Побочных».
- Свой файл пользователя `QuestCategories-user.json` (как `QuestStarts-user.json`) — поправить категорию.
- DLL читает файл при загрузке; натив для Papyrus/окна: категория квеста. Проверка — лог при загрузке
  (сколько квестов разложено), минимальный тест в игре не нужен до окна.

## Этап 3 — своё окно

Открывается хоткеем (и, если получится, из MCM), ставит игру на паузу, курсор мыши, закрывается Esc/хоткеем.
Две вкладки:
- **Квесты**: слева дерево категорий из этапа 2 со счётчиками («Минитмены 3/17»), справа список.
  Колонки: название, состояние (активен / не начат / выполнен), мир, расстояние, есть ли маркер.
  Фильтры: состояние (по умолчанию «невыполненные»), «только с маркером», мир; сортировка по расстоянию.
  Действия: отметить (как основной хоткей), поставить маркер старта для не начатого, исключить / вернуть.
- **Локации**: список непосещённых (из этапа 1), фильтры «замеченные / все», мир; сортировка по расстоянию;
  действие — поставить маркер, исключить.

### 3a. Инструменты и «пустое» меню (отдельная сессия)
- Сборка SWF без Adobe Animate: AS3 + бесплатный `mxmlc` (Apache Flex SDK или AIR SDK), проверить, что
  Scaleform игры принимает такой SWF (версия SWF/AS3). Шрифты — игровые (`$MAIN_Font` и т.п. из `fonts_*.swf`).
- Регистрация меню: F4SE `UI.RegisterCustomMenu` или CommonLibF4 из DLL — выбрать, что проще и надёжнее.
- Результат: хоткей открывает окно с надписью и кнопкой «Закрыть», игра на паузе, мышь работает.
  Это и есть минимальный тест.

### 3b. Обмен данными с DLL (отдельная сессия)
- DLL → окно: список квестов/локаций с полями (через GFx-значения / `Invoke`).
- Окно → DLL: «отметить», «маркер», «исключить» вызывают те же функции, что хоткеи (без дублирования логики).
- Пересчёт расстояний при открытии окна (не каждый кадр).
